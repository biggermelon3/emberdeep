操作要点
1. 张开任意一只手，用整只手的自然指向瞄准按钮。出现青色高亮和短射线后，用同一只手捏合确认。射线移开按钮即隐藏；头部朝向只用于摆放菜单。
2. 在装备握把处捏合拿起，然后先张手再捏合开火。空水箱不会被动恢复。
3. 消防栓补水：将装备蓝色接口靠近消防栓蓝环，停稳约四分之一秒。近距离会辅助接头朝向，但不会自动加水。
4. 对接后先张手，再在蓝色阀轮处捏合并松开；也可捏住后转动约45度。指示灯和水量条会显示注水。重复轻捏释放可提前关阀。
5. 满水自动停止。先张手，再在装备握把处重新捏合取走；再张手后才能重新开火。同一只手可依次完成这些动作。
6. 第二区域的小溪：对接装备，将滤水进水口捏起放入绿色圈并释放；握住泵柄拉约8厘米再推回，完整往返才增加水量。

设备验收（每项记录 Quest 3/PICO 4、系统版本、左/右手、坐/站姿）
[ ] 主菜单出现在正前方眼睛高度；New Game、Settings、声音开关、重新居中、Quit确认均可操作。
[ ] 手指捏合时指向仍稳定；只由指向按钮的那只手确认。持续捏合、换页或两手同时捏合不会连点。
[ ] 离开UI立即隐藏射线，灭火和操作水源时没有常驻SDK射线；视野外按钮不会被点中。
[ ] 近距离操作握把或水源时，UI不抢走这次捏合。
[ ] 握持位置和手模型视觉遮挡可接受；手不会在桌面或装备实体内部形成明显重叠。当前使用视觉裁剪，不是物理手碰撞或完整手指包覆姿态。
[ ] 空箱可到达消防栓；对接本身不给水；开阀、提前关闭、满水、断开均有清晰状态。左手和单手顺序操作都可完成。
[ ] 小溪只有完整有效泵动才加水；无效操作、切装备、重试、升级不会变相加满。
[ ] 遮住操作手、暂停或摘下头显会停水和取消蓄力；保持捏合恢复后不会误发射。
[ ] 水炮双手拉泵及替代操作保留；水流弹道、命中、火焰衰减和熄灭反馈容易辨认。
[ ] PICO 4记录实际CPU/GPU帧时间、掉帧和温度；Quest 3记录兼容性。不要用Editor帧率代替头显性能。

可复现构建
Unity 6000.3.21f1，Android / IL2CPP / ARM64；在独立Emberdeep工作区中运行：
Emberdeep > Build standalone Quest showcase
Emberdeep > Build standalone PICO showcase
对应入口：FireRescue.Editor.FireRescueBuilder.BuildShowcaseQuest / BuildShowcasePico。
构建输出各自的APK和manifest.json；manifest必须显示sceneWhitelistPassed=true、errors=0且仅包含EmberdeepCamp与EmberdeepFireground。
构建会临时应用Emberdeep名称、版本、图标和场景列表，并恢复原设置。
测试：Tools/Test-EmberdeepM1.ps1 -ProjectPath E:/GameDevelopment/MetaHackson/Emberdeep -OutputDirectory <新的证据目录>
